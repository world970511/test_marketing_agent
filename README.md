# 댓글 에이전트

채널의 최신 영상을 불러오고, AI가 영상 요약과 댓글 초안을 만들고, **크롬 프로필이 열리며 댓글을 한 글자씩 타이핑·게시·확인**하는 대시보드입니다.
심사자 컴퓨터에서 직접 실행하며, 화면은 `http://127.0.0.1:8000`(이 컴퓨터에서만 열림)에 뜹니다.

```
① 영상 불러오기  →  ② 영상 선택(요약 · AI 댓글 초안)  →  ③ 댓글 달기(크롬 프로필 → 타이핑 → 게시 → 확인)
```

- AI 키가 **없어도** 동작합니다. 제출 시점의 최신 영상 초안이 `drafts/`에 들어 있습니다.
- AI 키를 넣으면 초안이 없는 새 영상도 그 자리에서 초안을 만듭니다(선택).
- 웹에 올리는 서비스가 아니라, 내려받아 실행하는 프로그램입니다.

## 1. 10분 안에 띄우기 (Mac)

**준비물**: Google Chrome, Python 3.9 이상(`python3 --version`으로 확인), 인터넷

```bash
git clone https://github.com/world970511/test_marketing_agent.git
cd test_marketing_agent
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m src.main
```

실행하면 크롬에서 대시보드(`http://127.0.0.1:8000`)가 자동으로 열립니다. 종료는 터미널에서 `Ctrl + C`.

- `playwright install`은 필요 없습니다. 이미 설치된 **Google Chrome**을 그대로 씁니다. 크롬이 없으면 다른 브라우저로 대신 열지 않고 설치 안내를 보여 줍니다.
- 다음에 다시 실행할 때는 `source .venv/bin/activate` 후 `python3 -m src.main`만 하면 됩니다.

> **검증 범위**: 개발과 시험은 Windows 11 + Chrome에서 했습니다. macOS용 크롬 경로(`/Applications/Google Chrome.app`)와 `~` 경로 처리는 코드에 들어 있지만, Mac에서 직접 실행해 보지는 못했습니다.

## 2. 크롬 프로필 유튜브1 ~ 3 연결하기

댓글은 **프로필 폴더를 지정해 크롬을 여는 방식**(Playwright `launch_persistent_context`)으로 답니다. 크롬이 평소 쓰는 기본 프로필의 자동 제어를 막기 때문입니다.
프로필은 `config/config.yaml`의 `profiles`에서 이름과 폴더 경로로 지정합니다.

```yaml
profiles:
  - { name: 유튜브1, user_data_dir: "~/ChromeProfiles/유튜브1" }
  - { name: 유튜브2, user_data_dir: "~/ChromeProfiles/유튜브2" }
  - { name: 유튜브3, user_data_dir: "~/ChromeProfiles/유튜브3" }
```

- `name`은 화면의 프로필 드롭다운에 보이는 이름, `user_data_dir`은 그 프로필이 저장된 폴더입니다. `~`는 홈 폴더로 바뀝니다.
- 이 프로그램은 폴더 **경로만 크롬에 전달**하고, 폴더 안의 파일(쿠키·비밀번호 등)은 읽지 않습니다.
- 수정한 뒤에는 서버를 다시 실행하세요.

### A. 이미 로그인된 프로필 폴더가 있는 경우
그 프로필 폴더의 경로를 `user_data_dir`에 적으면 됩니다.
단, 크롬의 **기본 프로필 폴더**(Mac: `~/Library/Application Support/Google/Chrome`)는 크롬이 자동 제어를 막아서 지정할 수 없습니다. 프로필이 별도 폴더로 만들어져 있어야 합니다.

### B. 아직 로그인되지 않은 경우 (로그인 도우미)
구글은 자동 제어되는 창에서의 로그인을 막는 경우가 있어, **로그인은 평범한 크롬 창에서 사람이 직접** 합니다. 로그인 상태는 프로필 폴더에 남고, 게시기가 그 프로필을 그대로 이어 씁니다.

```bash
python3 scripts/login_profile.py 유튜브1     # 이름을 생략하면 첫 번째 프로필
```

1. 크롬이 열리고 구글 로그인 화면이 뜹니다. 계정으로 로그인합니다.
2. 유튜브 화면으로 넘어가면 **오른쪽 위에 내 프로필 사진(아바타)이 보이는지** 확인합니다.
3. 크롬 창을 **모두 닫습니다**. (열려 있으면 게시기가 같은 프로필을 열지 못합니다.)

프로필이 로그인되어 있지 않으면, 게시 시도 때 "이 프로필은 유튜브에 로그인되어 있지 않습니다" 라고 알려 주고 아무것도 게시하지 않습니다.

## 3. 사용법

| 칸 | 하는 일 |
|---|---|
| ① 영상 불러오기 | [영상 불러오기]를 누르면 우리 채널 5개가 목록으로 뜹니다. 채널을 누르면 그 채널의 최신 영상(썸네일 · 제목 · 채널 · 올린 날짜)이 보입니다. *(가점)* "링크로 직접 입력"에 영상 링크를 넣으면 허용 채널인지 확인한 뒤 바로 엽니다. |
| ② 영상 선택 | 영상을 고르면 목록이 사라지고 **영상 카드 → 영상 요약(+고민 한 줄) → AI 댓글 초안**이 보입니다. 초안 아래에서 **[직접 편집]**(글을 직접 고침)과 **[AI 재수정]**(수정 요청을 적으면 AI가 다시 씀)을 쓸 수 있습니다. |
| ③ 댓글 달기 | 프로필을 고르고(유튜브1~3 또는 "자동 배정") [댓글 달기]를 누르면 확인창이 한 번 뜨고, 크롬 프로필이 열려 **프로필 여는 중 → 영상 여는 중 → 댓글창 찾는 중 → 입력 중 → 게시 중 → 확인 중** 순서로 진행됩니다. 성공하면 "댓글 보기" 링크, 실패하면 사유와 화면 캡처가 표시됩니다. |
| 댓글 기록 확인 | 오른쪽 위 버튼. 어느 영상에 · 어느 프로필로 · 무슨 댓글을 · 성공/실패를 시간순으로 보여 줍니다. |

**[댓글 달기]는 실제로 게시됩니다.** 개발 중 시험은 `config.yaml`의 `test_videos`에 본인 테스트 영상 ID를 적고 그 영상으로만 하세요.

## 4. AI 키 넣기 (선택)

AI 키(Hugging Face 토큰)가 없으면 `drafts/`의 미리 만든 초안만 쓰이고, 초안이 없는 영상은 [직접 편집]으로 직접 쓸 수 있습니다.

```bash
cp .env.example .env
# .env 를 열어 HF_TOKEN= 뒤에 토큰을 붙여 넣기 (따옴표·공백 없이)
```

- 토큰은 Hugging Face → Settings → Access Tokens에서 만들고, Inference Providers 호출 권한을 켭니다.
- `.env`는 `.gitignore`에 들어 있어 커밋되지 않습니다. 토큰은 서버만 읽고 화면·로그로 내보내지 않습니다.
- 모델은 `config/config.yaml`의 `ai.model`에서 바꿉니다(기본 `Qwen/Qwen3-235B-A22B-Instruct-2507`).

초안을 미리 만들어 `drafts/`에 저장하려면(제출 직전 최신 영상 갱신 등):

```bash
python3 scripts/make_drafts.py              # 채널마다 최신 1개 (이미 있으면 건너뜀)
python3 scripts/make_drafts.py --force      # 이미 있는 초안도 다시 생성
python3 scripts/make_drafts.py -n 3         # 채널마다 최신 3개
python3 scripts/make_drafts.py --video ID   # 특정 영상만
```

## 5. 프로그램이 하는 일 / 하지 않는 일

**하는 일**
- 우리 채널 5개의 최신 영상 목록을 읽습니다(채널 RSS, 막히면 채널 페이지 `/videos`로 대체).
- 영상 페이지에서 제목·설명·자막·인기 댓글을 읽어 AI에게 줍니다(유튜브 공개 페이지, 로그인 없이).
- 지정한 크롬 프로필로 **선택한 영상 한 곳**에서 댓글을 작성·게시하고, 내 댓글이 보이는지 확인합니다.
- 게시 기록(`data/log.json`)과 실패 화면 캡처(`data/screenshots/`)를 이 폴더 안에 남깁니다.

**하지 않는 일**
- 쿠키·비밀번호·브라우저 저장 정보를 읽거나 저장하지 않습니다.
- 구독·좋아요·설정 변경 등 댓글 작성 외의 동작을 하지 않습니다.
- 허용된 영상 페이지 밖으로 이동하지 않습니다.
- 유튜브와 AI 서비스 말고는 어떤 데이터도 외부로 보내지 않습니다.
- 프로젝트 폴더 밖의 파일을 읽지 않습니다.
- 운명원을 직접 이용해 본 것처럼 지어낸 후기를 쓰지 않습니다.

### 안전 규칙을 지킨 방법 (코드로 확인할 수 있는 위치)

| 규칙 | 지킨 방법 | 코드 |
|---|---|---|
| 쿠키·비밀번호·저장 정보를 읽거나 저장하지 않는다 | 프로필 폴더는 **경로만 크롬에 전달**합니다. `cookies()`·`storage_state`·`Login Data` 같은 접근이 없습니다. (유튜브 동의 화면을 넘기려고 고정값 `CONSENT=YES+1` 을 요청 헤더에 보내는 것은 사용자 쿠키가 아닙니다.) | `src/poster.py`, `src/youtube_feed.py`, `src/youtube_resolve.py` |
| AI 키를 화면·로그·외부로 내보내지 않는다 | `.env`는 서버만 읽고, 화면에는 "설정됨 여부(true/false)"만 전달합니다. 오류 메시지에는 오류 종류만 넣고 값은 넣지 않습니다. `.env`는 커밋되지 않습니다. | `src/config.py`, `src/app.py`, `src/draft.py`, `.gitignore` |
| 우리 채널 영상(과 본인 테스트 영상) 페이지 말고는 열지 않는다 | 게시기는 대상 영상의 `watch` 페이지만 열고, 그 밖의 최상위 이동은 막습니다. 예외는 이미 로그인된 프로필이 세션을 이어받는 **자동 로그인 확인 이동**(`ServiceLogin?...passive=true` 등)뿐이며, 계정·비밀번호 입력 화면은 계속 막습니다. 막은 주소는 실패 사유에 표시됩니다. | `src/poster.py` (`_is_allowed_navigation`) |
| 댓글 작성 외의 동작을 하지 않는다 | 구독·좋아요·설정 관련 셀렉터와 코드가 없습니다. 쓰는 셀렉터는 댓글창·입력칸·게시 버튼·댓글 목록뿐입니다. | `src/selectors.py` |
| 유튜브와 AI 서비스 말고는 외부로 보내지 않는다 | 접속처는 `youtube.com` · `ytimg.com` · Hugging Face 추론 API 뿐입니다. (유튜브가 로그인 확인을 위해 이동시키는 `accounts.google.com` 은 크롬이 거치는 구글 로그인 서비스입니다.) 분석 도구·CDN·외부 폰트가 없고 화면은 순수 HTML/CSS/JS 입니다. | `src/` 전체 |
| 대시보드 폴더 밖의 파일은 읽지 않는다 | 읽는 파일은 `config/config.yaml`, `.env`, `drafts/`, `data/` 뿐입니다. 크롬 프로필 폴더는 경로만 크롬에 넘기고 이 코드는 읽지 않습니다. | `src/config.py` |

> 참고: `scripts/login_profile.py`(로그인 도우미)는 사용자가 직접 실행하는 별도 스크립트로, 구글 로그인 페이지를 크롬으로 열기만 하며 프로필 안의 파일은 읽지 않습니다.

### 운영 규칙 (코드에서 강제)

| 규칙 | 동작 | 코드 |
|---|---|---|
| 허용 범위 | 우리 채널 5개의 영상(+`test_videos`)에만 게시합니다. 직접 입력한 링크도 영상의 채널을 확인해 막습니다. | `src/guard.py`, `src/youtube_resolve.py` |
| 영상당 댓글 1개 | 이미 댓글을 달았거나 진행 중인 영상은 프로필이 달라도 막습니다. | `src/guard.py`, `src/eventlog.py` |
| 하루 게시 상한 | 기본 10개(`limits.daily_max_comments`). 넘으면 막습니다. | `src/guard.py` |
| 문구 규칙 | 40~120자 · 링크/해시태그 금지 · `운명원` 언급 필수 · 직접 이용한 후기처럼 쓰기 금지 · 깨진 글자 금지. 화면에서 고쳐도 서버가 게시 직전에 다시 검사합니다. | `src/agent/rules.py` |
| 동시 게시 1개 | 게시 중에는 다른 게시를 받지 않습니다. | `src/app.py` |
| 기록 | 영상 · 프로필 · 댓글 · 성공/실패(+사유)를 시간순으로 남깁니다. | `src/eventlog.py` |

## 6. 설정 파일 (`config/config.yaml`)

| 항목 | 설명 |
|---|---|
| `profiles` | 크롬 프로필 이름과 폴더 경로 |
| `channels` | 불러오기·게시가 허용되는 채널 5개 |
| `test_videos` | 개발 중 게시 시험용 본인 영상 ID(여기 적은 영상만 우리 채널이 아니어도 허용) |
| `videos_per_channel` | 채널마다 불러올 최신 영상 수 |
| `comment` | 글자 수 범위(`min_chars`, `max_chars`)와 댓글에 들어갈 브랜드 이름 |
| `limits.daily_max_comments` | 하루 게시 상한 |
| `ai` | Hugging Face 모델과 provider |

## 7. 폴더 구조

```
README.md  PROCESS.md  .env.example  requirements.txt
config/config.yaml        설정
drafts/<영상ID>.json       영상별 미리 만든 요약 · 고민 · 댓글 초안
scripts/                  make_drafts.py(초안 사전 생성), login_profile.py(프로필 로그인 도우미)
src/                      main.py(시작점) · app.py(서버) · poster.py(크롬 게시) · guard.py(운영 규칙)
                          agent/(프롬프트 · AI 호출 · 규칙 검사) · static/(대시보드 화면)
data/                     실행 중 생기는 게시 기록·실패 캡처 (커밋 안 됨)
```

## 8. 검증 현황과 한계

**확인한 것** (Windows 11 + Chrome)
- 채널 5개 영상 목록 표시(RSS가 막혀도 채널 페이지로 대체되는 것 포함)
- AI 초안 생성·AI 재수정, 규칙 검사(깨진 글자 · 문구 겹침 · 후기 날조 · 길이)
- 크롬 프로필(유튜브1)로 **본인 테스트 영상에 타이핑 → 게시 → 내 댓글 확인까지 성공**, 같은 영상 재게시 차단
- 허용 채널 밖 영상 거부, 영상당 1개·하루 상한 동작

**확인하지 못한 것 / 한계**
- macOS에서의 실행, 유튜브2·3 프로필의 로그인과 게시
- 시험한 게시 영상은 Shorts 한 개입니다. 일반(가로) 영상의 댓글창은 같은 셀렉터를 쓰지만 별도로 확인하지 못했습니다.
- 성공한 게시는 서버 API 호출로 시험했고, 화면의 [댓글 달기] 버튼으로 끝까지 확인한 것은 아닙니다.
- 가점 중 **"뜨기 직전 영상 찾기"는 구현하지 않았습니다.** 프로필 선택/자동 배정, 링크 직접 입력, AI 키로 새 영상 초안 즉석 생성은 구현했습니다.
- 유튜브 화면 구조가 바뀌면 `src/selectors.py` 수정이 필요할 수 있습니다.
- 하루 상한과 영상당 1개는 이 컴퓨터의 `data/log.json` 기록을 기준으로 합니다.
- AI 초안은 영상에 없는 말을 지어낼 수 있으므로, 게시 전에 화면에서 한 번 읽어 보세요. ([직접 편집] / [AI 재수정])
